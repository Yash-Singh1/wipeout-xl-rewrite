# WebGL disc loading and rendering

iOS 16.2 Safari in the iPhone 8 simulator could not allocate the contiguous WASM heap needed for the full Japanese disc. The loader now keeps audio-only raw tracks in 1 MiB JavaScript chunks. The CD reader copies the requested 2352-byte sector into a separate audio buffer. Data files and files shared by data and audio tracks retain their full WASM mappings. WAV files also retain full mappings for their RIFF parser. Audio bytes and rendering resolution are unchanged.

With the full Japanese disc, the observed WASM heap falls from 827,719,680 bytes to 268,435,456 bytes. This is contiguous WASM memory, not total process memory. JavaScript still holds the raw music. A single BIN containing both data and music still requires its full mapping. Cache writes may temporarily retain additional copies.

The loader rejects truncated or oversized streams and releases native allocations after a failed load so a retry does not leak them. Audio has its own sector buffer because the mixer can retain that pointer while the same thread reads cooked data sectors.

WebGL texture uploads no longer call glGetError after each upload. Allocation and shader checks remain, and native OpenGL retains its upload checks. A browser sample of the prior renderer recorded tens of thousands of these polls during a race. A two-bucket decoded-page cache experiment passed rendering checks but was left out because background-browser throttling prevented a reliable full-game performance comparison.

Muted web runs skip opening an audio device. Their clock already follows video fields, so SDL's dummy audio timer is unnecessary. The earlier dummy timer repeatedly raised a function-signature exception. This change does not establish that normal audio playback is fixed. Development sessions remain muted.

## Validation and limits

The full disc loads and reaches a race in Safari on the iPhone 8 iOS 16.2 simulator. Touching the canvas reveals the touch controls. Simulator results establish compatibility only, not physical iPhone GPU throughput.

Desktop checks use the built-in browser with the Apple M5 Pro ANGLE Metal renderer and 3x internal resolution. Early steady samples reach approximately 60 presentations and 30 game updates per second. Long background-browser samples develop roughly one-second timer delays and are unsuitable for throughput comparisons. No sustained device FPS or end-to-end speedup is claimed from those samples. Test pages use separate versioned JS/WASM URLs to avoid accidentally profiling cached builds.

`sh tools/webtest/run.sh` checks the actual page's classification and loading functions, fragmented streams, allocation failures, retry cleanup and RIFF fallback. Its WASM test exercises the real C-to-JavaScript sector bridge across chunk boundaries and verifies that cooked data reads preserve a held audio sector. The native bug suite includes OpenGL and Metal comparisons for palette changes, cache overflow, wrapped pages, mixed passes, meshes, HUDs, presentation and readback. The merge from main also checks that disk-backed recorder images remain visible in its new presented-frame filter.

The parent PC matching gate could not run because the Docker daemon's socket was unavailable. No parent decompilation source was edited.


## iOS 16 race draw stalls

A foreground iPhone 8 / iOS 16.2 Safari simulator test exposed a separate, severe race bottleneck. The animated menu reached 60 FPS, but racing fell into single digits and sometimes below one presentation per second. This was reproducible after clearing accumulated Wipeout test tabs.

Native samples showed WebContent waiting in canvas preparation for the graphics process. The graphics process was mostly inside ANGLE's drawArrays implementation, mapping a generated buffer and waiting for Metal command completion. The same trace included provoking-vertex index generation. Our game shader's flat integer varyings trigger this older ANGLE Metal path.

WebGL now sends its per-triangle metadata through high-precision floating-point varyings, then rounds and converts it back to the original integer types in the fragment shader. Every vertex receives identical texture, palette, window, HD and blend metadata from gpu_renderer.c:Add. Per-vertex geometry, colours, UVs and exact-depth/back-facing flags retain their original behaviour. Constant metadata therefore remains constant across each triangle, while the shader no longer requires provoking-vertex emulation. Internal resolution, depth passes, blending and draw order are unchanged. Desktop OpenGL retains flat varyings; Metal's shaders are unchanged.

A native GL test build can select the WebGL interface with PORT_TEST_WEBGL_METADATA. The GPU regression runner compares all 512 colour/depth output hash pairs with the original flat interface. They match byte for byte, including differing per-vertex depth flags, palettes, texture windows, wrapped pages, HD replacements, mixed transparency, overlap and rendering scales. Full OpenGL/Metal regression suites and macOS/Web builds also pass.

The final compiled WebGL build is tested directly in Safari, with no JavaScript shader override. Local logs and native samples are in the ignored build/web-opt/metadata and build/web-opt/simulator directories. These measurements describe the simulator on an M5 Pro Mac, not physical iPhone throughput. Test audio remains disabled.

The active-race interval from seconds 15 to 55 averages 60.0 FPS over 40 seconds. The longer run also includes the end-of-race screen because the unattended ship eventually times out. The compiled simulator run averaged 60.001 displayed FPS and 29.975 game updates/second over 59.999 seconds, with 3,600 presentation intervals. The p99 interval was 25 ms, the maximum was 30 ms, and none exceeded 33.3 ms. Settings were 3x rendering, widescreen, foreground Safari, recording off and muted audio. An earlier matched-setting foreground race sample averaged 5.656 displayed FPS and 6.953 updates/second; native traces showed repeated draw-time Metal waits. The shader trial separately held roughly 60 FPS for more than two minutes before the final compiled build was tested.


## Muted phone loading over the LAN

The full Japanese disc was 662,967,648 bytes, including 571,307,856 bytes of music. The old HTTP phone page downloaded every track and kept raw music in JavaScript even while muted. A physical iOS 16.3 Chrome report described a crash when the race loaded. That makes memory pressure a plausible cause, but no physical-device crash log was available to establish it.

`tools/serve_web.py` now generates the muted phone page with the existing data-track-only disc support. It retains the complete 91,659,792-byte data track and all game graphics. The virtual silent music tracks are supplied by the existing disc reader. The full-disc web page is unchanged.

The helper serves data in fingerprinted 1 MiB chunks, with gzip and immutable HTTP caching. The Japanese track transfers 59,891,626 compressed bytes, plus the game JS/WASM. Four requests run at a time, and decoded chunks are copied into WASM in order. The loader does not retain the entire track in JavaScript or make a full-track Cache API copy before starting the game. The bounded HTTP cache works on a plain LAN HTTP address, where the browser Cache API is unavailable. The simulator's cached reload issued zero additional chunk requests.

Validation checks gzip and identity HTTP responses, content lengths, the complete original data SHA-256, invalidation when data changes, ordered loading, the four-request bound, truncated chunks, HTTP failure and cancellation cleanup. Existing web disc-sector tests pass. Rendering remains 3x widescreen, recording off and audio muted. Physical iOS 16.3 needs a retry on the updated page to confirm whether this resolves the reported crash.


## Phone orientation and visible viewport

The canvas previously relied on SDL's fill-document mode and its window-resize callback, which leaves an inline CSS size. Mobile orientation and browser-toolbar changes can publish their final visible dimensions later or through visualViewport alone.

The web canvas now has CSS-controlled bounds. A pre-runtime viewport bridge follows visualViewport resize/scroll, window resize, orientation and visibility changes. Rotation schedules bounded follow-up measurements for delayed dimensions. Changes coalesce to animation frames; unchanged sizes do not dispatch further resize events. Pinch zoom is not applied twice, and hidden zero-sized viewports do not collapse the drawing buffer. SDL's external-size callback updates its logical window and the high-DPI drawing buffer together, so the renderer and touch controls use the same size.

Tests cover delayed orientation, portrait/landscape transitions, toolbar/keyboard height changes, DPR changes, duplicate events, hidden viewports and the window-only fallback. The compiled iOS 16.2 simulator build was checked in both orientations: 375x548 CSS pixels with a 750x1096 buffer in portrait, then 667x325 with a 1334x650 buffer in landscape. Touch controls move to the new bounds and steady presentation returns to roughly 60 FPS. The current LAN phone page includes the bridge; existing tabs need a reload.

## Bounded music streaming and static hosting

The phone helper now marks audio-only tracks for streaming. Startup maps a 64 KiB prefix per track for format detection, while data files retain their existing WASM mappings. The original RIFF-in-BIN fallback still maps the full WAV for its native parser. Local disc uploads retain their existing chunk storage.

One shared LRU cache retains at most six decoded 1 MiB music chunks across all songs. At most two fetches run at once. Sector reads schedule two chunks ahead, roughly twelve seconds of original PCM. Warm reads copy synchronously into the separate C audio sector buffer. Explicit raw-sector reads can await a cold fetch through Asyncify. The music mixer instead requests missing sectors in the background and holds its music position until the bytes arrive, while SPU effects keep advancing. A failed fetch discards partial bytes and backs off before retrying; close and failed startup abort pending work. No lossy audio conversion is used.

Unit tests cover ten songs, forward/backward seeks, exact bytes across chunk boundaries, cache eviction, concurrency and memory bounds, invalid ranges, HTTP errors, truncation, offline errors, retry backoff and close. The actual compiled C bridge is tested with both resident and streamed music, including WASM heap growth during an asynchronous fetch and a held music pointer across cooked data reads. Loader tests verify prefix-only allocation and cleanup after header failure. Native Mac and Web builds and the complete web tests pass.

The iOS 16.2 simulator raced with real audio output processing, with the final speaker gain silenced only for development. The active-race interval at game seconds 60 to 90 averaged 60.000 displayed FPS and 29.983 updates per second, with p99 presentation interval 23 ms and maximum 27 ms. The observed decoded music cache peaked at 6,291,456 bytes. The saved sample had 113 seconds of running audio and no runtime exceptions. Desktop playback also retained the six MiB cache. Portrait/landscape rotation kept audio active. This is host/simulator evidence; the physical iOS 16.3 phone still needs a retry. Cache figures exclude per-track prefixes, temporary network buffers, WASM memory and GPU allocations.

Streaming uses ordinary file requests. `tools/serve_web.py --music --export build/web-static` creates a static site with index.html, a muted phone.html alternative, CUE files, a matched JS/WASM pair and content-addressed raw binary chunks. It requires no Python server, API, service worker, byte-range support or custom compression headers after export. Relative URLs support a site subdirectory. Tests serve the nested export with a plain static-file handler and verify the runtime, full audio chunk bytes and CUE. The exported game is also exercised in the browser through ordinary static-file serving. These files are prepared locally; no production site deployment is performed.


## iPhone XR audio activation and presentation follow-up

A physical iPhone XR on iOS 16.3 reported no music or effects, oscillating frame rate and a tab crash after race loading. The simulator's successful output processing did not establish audible output or physical-device memory compatibility.

The web page now waits for Play with sound after disc loading. It creates and resumes Web Audio directly in that real user gesture, then supplies the already running context to SDL before main starts. A rejected or suspended activation stays on the panel with retry and explicit muted-play choices. If playback is interrupted later, Enable sound and subsequent trusted input can resume it. Tests cover gesture ordering, single startup, interruption, failure, a pending resume timeout, retry and muted startup. The simulator starts the real output device through the visible Play button with nonzero output callbacks. A desktop isolation test also produced nonzero SPU output while only the CD input was silenced.

SDL's WebGL SwapWindow only yields through Asyncify. It previously yielded before the platform's own ShowPicture handoff, creating two task boundaries for one presentation. The WebGL device now leaves that handoff to ShowPicture. The canvas requests opaque color without default depth or stencil; game alpha and depth still live in their own offscreen targets.

ShowPicture now waits for requestAnimationFrame and a following task before the game produces another picture. Removing the extra SDL yield exposed a race in the old deferred handoff that could submit multiple pictures per browser refresh. Hidden pages use a 16 ms timer instead of waiting indefinitely for a suspended animation callback. The presentation test executes the actual JavaScript body from video.c and checks both paths.

Decoded indexed textures and streamed geometry no longer retain CPU migration copies in a web build with only one backend. Pack-buffer readback retains its required CPU storage. Adding a second web backend automatically restores migration copies; native backend migration is unchanged. This avoids up to 32 MiB of indexed-page shadows plus repeated per-frame geometry copies and reallocations. Initial WASM capacity is 160 MiB with growth allowed. The observed race run used 192 MiB; capacity is not total process memory or measured resident use. The single-backend upload path and float metadata preserve all 512 reference color/depth hash pairs. Native OpenGL regression checks, Mac/Web builds and the complete web suite pass.

A browser recording captured real bright scene frames, with touch controls left intact. Tracing uploaded geometry identified full-screen untextured quads at 228/255 brightness, the exact value assigned by the rain/lightning logic in racectrl.c. These observed flashes are intentional game effects and remain enabled. This does not establish that every future report of a white frame has the same cause.

The local helper also prepares phone-music-check.html. This opt-in page preserves normal audio output and reports browser audio state, real callback activity, sampled nonzero PCM, FPS, WASM capacity, bounded music-cache/fetch state, context losses, graphics API call counts/times and recent output to the same local host once per second. The helper stores the latest bounded snapshot per session under build/phone-diagnostics. It deliberately avoids creating a WebGL context before SDL, and rejects oversized or invalid diagnostic requests. Static exports exclude the diagnostic hook and still need no backend.

The first physical XR diagnostic session, revision b9f7640b, still failed. It reported a running 48 kHz audio context, a real SDL playback device, 1,535 nonzero output blocks and no WebGL context loss before the final snapshot. Music fetches had no recorded failures and the shared music cache stayed at six MiB. Presentation fell as low as roughly three FPS while game updates remained near thirty. This establishes that the reported silence occurs after the mixer, but does not establish the tab termination's cause.

The next candidate routes the actual SDL ScriptProcessor output through a MediaStreamAudioDestinationNode and an HTML audio element on iOS. The Play gesture starts both context and media playback. This uses media playback for the mixed audio rather than the direct ambient Web Audio destination. Diagnostics report the media element's paused, ready and error states. No microphone permission or separate silent audio loop is used. The simulator reports playing media with nonzero mixed samples; physical audibility still needs verification.

The decoded texture cache also churned during the scripted race, decoding and uploading about 1,500 complete 256-by-256 pages per second on the host. WebGL now defaults to the existing raw VRAM sampler, avoiding those CPU decodes and the 32 MiB decoded texture array. A minimal valid array remains bound for the shader's unused sampler. WIPEOUT_DECODED_CACHE=1 restores the cache for diagnosis; native backends retain their existing default. Cached and raw paths reproduce all 512 reference color/depth hash pairs on the GL regression driver. The extra dependent texture lookup may have a device-specific GPU cost, so physical XR timings remain necessary.

The physical XR then confirmed audible but stuttering audio on revision 3c9c07f1. It still terminated after race loading. Its final snapshot had no recorded music-fetch error or context loss, with 192 MiB WASM capacity. Presentation was more stable according to the user, but the remaining failure was not resolved by raw VRAM sampling or media routing.

Web output now queues the existing SPU/CD mixer samples into 2,048-frame AudioBuffers at their original 44.1 kHz rate. AudioBufferSourceNodes are scheduled contiguously against AudioContext.currentTime. This removes SDL's main-thread ScriptProcessor deadline and audio callbacks that re-enter WASM while Asyncify is suspended. A 120 ms initial lead bridges short stalls. The schedule caps its lead at 350 ms, releases finished nodes, records underruns/dropped frames and preserves the unplayed sample offset across recorder pause/resume. Native SDL audio is unchanged. The iOS media destination still carries the actual mixed audio. This path uses standard Web Audio on HTTP LAN origins as well as HTTPS static hosts; it needs no worklet, shared memory or additional hosting headers.

GPU presentation also inserts WebGL 2 fences and waits asynchronously when two frames remain outstanding. Browser refresh pacing alone does not establish GPU completion. The wait polls with zero timeout and yields to another browser refresh, or a timer while hidden. Completed/context-lost fences are released, and diagnostic snapshots report outstanding work, waits and failures. This bounds queued frames without changing resolution or draw ordering. It is a precaution against accumulating driver work, not proof of the physical tab termination's cause.

Scheduled-output tests verify exact channel samples, consecutive buffer timing, original sample rate, recovery after a long stall, bounded live nodes during fast-forward, close and pause/resume. The compiled C-to-JavaScript bridge is also checked across WASM heap growth. Real OfflineAudioContext renders in Chromium and iOS 16.2 WebKit reproduce both adjoining buffers with zero sample error. A 165-second simulator session included repeated 100 ms main-thread stalls every two seconds after warmup. Development output alone was muted at the final gain node. These checks do not establish audible quality or crash recovery on the physical XR.

All page controls disable text selection and the iOS touch callout. Text entry fields retain selection for editing.

## Startup storage wait

The XR's next attempt remained at Preparing music with all ten music-header fetches finished, no pending fetch and no network failure. That label was left on screen through the following cache/storage work. Chunk-based loads now skip the unused whole-disc Cache API step, and the page labels saved-data restoration separately.

Saved-data restoration has a five-second deadline. IDBFS local stores/removals under /libsdl are staged until the entire restore transaction succeeds. On timeout or error, the staged operations are discarded, late callbacks remain guarded, and the game can start with a visible notice that changes will not be saved for that session. Autosave stays disabled in that case, so defaults cannot replace existing browser saves. Healthy restores retain the existing IDBFS database, paths and record format. Autosave begins after Play, serializes transactions, coalesces requests received during a write, stops after a timed-out write, and skips periodic writes in hidden tabs.

Tests cover successful restoration, a blocked read, partial staged results, late writes/removals after timeout, an unrelated mount, read errors, write serialization, write timeout and hidden tabs. Chromium and iOS 16.2 WebKit both reach Play with a deliberately suppressed storage callback, show the unsaved-session notice and launch the game. A real Chromium save/reload roundtrip also succeeds. Phone diagnostics now include the visible startup status and saved-data phase/error, rather than requiring the last music message to identify the wait.

## Physical XR compiler memory investigation

The USB recording on an iPhone XR running iOS 16.3.1 identified a native WebContent high-water termination. The system log reported 1,573,155 KiB at the kill. WASM capacity remained 192 MiB, the music cache remained six MiB, and the presentation queue retained at most two fences with no context loss. Those bounded allocations did not explain the process-memory spike.

A native Time Profiler recording attributed substantial CPU time to Wasm Worklist Helper Threads. Symbolication against the matching on-device JavaScriptCore UUID identified BBQPlan::compileFunction, parseAndCompileAir and GraphColoringRegisterAllocation::allocateOnBank, including its coalescing and spill selection. GPU-only upload, draw and presentation probes did not reproduce the same growth. Replacing integer uniform setters with equivalent vector setters also failed to resolve it. These were diagnostic probes, not retained renderer changes.

The release linker had merged SDL_main into a 353,295-byte Asyncify body. Web builds now suppress LLVM function inlining before linking and let Binaryen inline small helpers with an 8,192-byte combined-body bound. The largest final body in the tested build is 27,720 bytes; SDL_main is 18,652 bytes. Full Asyncify suspension coverage remains enabled, including indirect calls. Native compilation flags, render resolution, shaders and texture sampling remain unchanged. WebGL entry points are linked directly instead of looked up through SDL procedure-address wrappers. A symbol map accompanies the web build for profiling.

The resulting muted normal race ran for more than five minutes on the physical XR without another termination. Native page-category memory settled instead of reproducing the rapid compiler spike. Inspector categories are not total resident memory, and navigation history retained another WASM instance in the inspection process. A heap snapshot confirmed that retained context, so these numbers must not be presented as a clean single-tab memory benchmark. The complete web test suite passes. A following music-enabled normal race completed 300 USB samples, ending at page second 316.963, without termination. The real AudioContext and iOS media route remained running, with nonzero mixed PCM and bounded scheduling; only a final development gain node silenced the speaker. Some underruns still occurred. Presentation remained roughly 20 to 30 FPS while game updates held near 30 per second, so the physical 60 FPS target and glitch-free sound remain unresolved. A follow-up xctrace recording could not export its samples, and the WebKit ScriptProfiler stop request timed out. Neither is counted as successful follow-up CPU evidence. The tested build is published by the local phone helper and exported statically; no production deployment was performed.

## Title confirmation sound and first-menu initialization

USB PCM and scheduling captures reproduced the title confirmation being interrupted at the first menu. Phase markers put the remaining stall inside ShowMenu rather than model loading, CD command startup or a slow graphics API call. Its first button prompt lazily built the complete controller-icon atlas. Each raster pixel reparsed letter-stroke strings with SDL_sscanf, including repeated floating-point conversions.

The letter strokes are now numeric constants. The distance calculations and painting remain unchanged, and the web startup prepares the atlas after GPU initialization but before the game opens its audio device. First-menu drawing therefore uploads no newly generated icon data. Native glyphs retain lazy initialization and use the faster rasterizer. The full atlas hashes are unchanged within each runtime: 83b87e9f3314c9c2 on native ARM64 and 2c8f3901905d666a in WebAssembly. Tests also compare 103,684 distance samples with the former string representation and check that preparing the atlas twice uploads only once.

In the captured physical XR transition, the previous 1,153 ms gap in audio production became a maximum of 70 ms. The candidate's two startup underruns and 4,096 dropped startup frames did not increase across the confirmation effect and menu transition. Sources had looping disabled. The final speaker gain was zero during development; this is a PCM/scheduling check rather than a recording from the physical speaker. Frame-rate work remains separate.

A second issue was found in cold streamed music reads. DiscRawSector could suspend the whole SPU mixer while fetching a missing chunk. CD playback now polls a nonblocking audio-sector path, requests at most one pending fetch per track, and retries once per sector period. Until ready, only music is silent and its sector/sample position stays unchanged. Once ready, playback resumes at the first missing sample. Resident audio, explicit raw/data reads, native CD behavior and cache limits are unchanged. A compiled regression fixture delays a real chunk fetch, confirms the SPU one-shot finishes once without yielding to JavaScript, checks request coalescing, grows the WASM heap during the fetch, and verifies every resumed music sample.

The web suite, native regression suite and Mac build pass. Native I/O tests also pass after supplying missing standalone-harness definitions for NTSC timing, field count and inactive link state; the optional external SPU-oracle recordings were unavailable. Temporary game-source phase markers and experimental file-boundary servicing were removed.
